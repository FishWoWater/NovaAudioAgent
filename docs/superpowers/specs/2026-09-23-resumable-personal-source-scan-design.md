# Resumable personal source scan and live workbench acceptance

Status: Design and written specification approved in conversation on 2026-09-23; amended for the user's first-open incremental update requirement and Claude Opus 5.5 review. Supersedes the isolated-copy acceptance method in the workbench content relevance design for final acceptance.

## Intent and boundaries

An authorized whole-computer source should surface useful, attributable excerpts from recent work quickly, continue broader coverage fairly, and recover after interruption. Empty workbench pages are valid when no eligible evidence exists. The user-selected directory inside an existing computer grant is a priority, not a new grant. Hidden paths are excluded by default except an explicitly selected path that passes the existing sensitive-path policy. Activity is an ordering clue, never proof of authorship, ownership, interest, or commitment.

The final acceptance must run the production native desktop window against the original local profile and actual files. A copy may be retained solely as a rollback backup; a run on a copy is not acceptance. No fixture data may enter the acceptance profile. Scan diagnostics, model invocations, candidate counts, and rendered cards are reported separately.

## Observed failure

The original source state inspected on September 23 had `state:error`, `scan_pending:true`, 100 indexed files, 374 queued directories, 10 pending files, and 51 saved failures. `scan_pending` means unfinished work; it is not an error code. The existing computer walker can leave `body_budget` and `index_limit` files in `walk.pending`, causing repeat work. Its failures accumulate across batches, so old per-file failures keep `state:error`; a terminal error can create a 51st failure beyond the schema's 50-item cap. It saves an offset into a newly sorted directory listing, so directory edits between batches can cause misses or duplicates. Knowledge ingestion currently reduces distinct parse, screening, embedding, and store failures to `ingest_failed`, limiting diagnosis. The previous acceptance harness used a copied profile and its own BrowserWindow, so it did not exercise the daily native app.

## Architecture and data contract

Separate **discovery**, **selection**, and **content ingestion**. Discovery records safe metadata for supported files without claiming to understand them. Selection ranks projects and files, enforcing fair budgets. Ingestion reads selected files through the existing authorized knowledge path, obtains screened text, records a content fingerprint and excerpt, and only then makes evidence available to workbench selection. A filename or metadata-only entry can never create a Todo, idea, goal, or profile claim.

Keep the persisted source's grant and tracked-file identity. Evolve the walk checkpoint compatibly where possible; if a new disk version is required, provide a tested down-migration before opening the daily profile. The checkpoint stores a bounded directory ledger keyed by canonical path, with filesystem identity where available, scan generation, completion state, retry eligibility, and diagnostics; old generations are pruned after reconciliation. A completed directory is not re-enqueued in the same generation merely because its parent is revisited. File records retain path, unit/root, stable source ID, device/inode where available, size, high-resolution modification time where available, content fingerprint, excerpt/evidence IDs, validity, and current ingestion state. Metadata is a cheap change filter, not an assertion that content is unchanged: a file selected for ingestion is read and hashed; identity and metadata are checked before and after the read. A periodic bounded content recheck catches same-metadata edits missed by events. Every derived observation and card is tied to the file version; invalidation hides stale derived content before a replacement becomes visible. Existing valid evidence remains available while the rest of the source scans.

## Traversal and scheduling

Automatically skip hidden components, sensitive paths, symlinks, dependency/build/cache trees, and inaccessible system roots. Apply the user's explicit priority directory only inside the existing grant; a selected hidden path remains subject to sensitive-path policy. Do not scan `.git` contents. Detect repository boundaries via a `.git` marker and cache bounded Git activity probes per root. Give the current authorized workspace and selected directories high priority, then use recent commits and file changes as weaker signals. Use weighted fair scheduling across roots so one active repo cannot starve other authorized areas. Reserve separate bounded budgets for directory enumeration, stat calls, content bytes, ingestion time, and per-root early evidence. Budget exhaustion pauses or completes the affected work item with a reason; it must never leave an item in an immediate retry loop.

Enumerate a directory as one logical unit using streaming entries with bounded memory. Admit discovered children idempotently in bounded chunks, recording which children were seen in the current pass; commit directory completion and deletion reconciliation only after reaching the end and confirming the same directory identity. If interrupted or changed during enumeration, restart that directory idempotently; do not persist an array index into a listing that may have changed. A very large directory may be marked partial with an explicit reason if a hard safety cap is reached; it must not repeat the same first chunk forever or claim complete coverage. Never delete prior evidence because a partial pass did not see it. A missing or unmounted root is unavailable, not deleted; deletion requires a complete parent pass on the same reachable filesystem. Queue operations are deduplicated by canonical path and source generation using the ledger, rather than a linear search of the current queue. Fair scheduling rotates across roots inside each priority tier and gives unused turns to other tiers. Preemption and process restart preserve progress without multiplying work. Keep the current atomic temporary-write, fsync, and rename protection for JSON state and reduce redundant full-state writes without weakening the pre-ingestion and pre-invalidation crash fences.

For incremental updates, start with periodic bounded metadata and content reconciliation and use platform file-change notifications where available. Notifications schedule affected directories/files; they do not alone certify completeness. The first implementation treats Node watcher events only as hints because they do not expose the macOS FSEvents loss flags or a durable event cursor. Startup, watcher error, or watcher restart schedules a bounded ledger reconciliation; selected/current roots are checked more often than other roots. A future native FSEvents adapter must recursively rescan when events are coalesced or dropped. Avoid making Watchman or a new native service mandatory for the first implementation. External volumes and unavailable roots are reported as partial coverage and retried with backoff, not silently treated as deletion.

## Outcome and error semantics

Every pending item ends in one of: indexed, excluded, budget-deferred to a later eligible window, transient retry with bounded backoff, or terminally skipped with a diagnostic. Each deferred/retry item records its next eligible time and attempt count. A batch must finish an item or move its eligibility forward; a no-progress batch backs off rather than hot looping. Full index capacity is a terminal partial-coverage reason until capacity changes, not a timed retry. Capacity limits produce an explicit partial-coverage reason. `scan_pending` reflects unfinished work, including scheduled retries, even when none is immediately eligible; it does not mean `error`. Observation delivery has a separate backlog and retry state, so it cannot keep file scanning pending. Historical diagnostics remain inspectable but do not by themselves determine the current state. Per-file screening rejection, unsupported format, transient file change, and unreadable directory are local outcomes. Source-level `error` is reserved for failure to open/persist the source, broken authorization, or a continuing failure that prevents useful progress. Keep grant, health, and coverage distinguishable in the snapshot while preserving the legacy state field for existing readers; pause or disconnect must not be overwritten by a scan result. The UI reports partial coverage and the affected reason without implying all indexed content is invalid.

Preserve the specific reason from knowledge parsing/screening/embedding/storage across the service boundary as a bounded code, with no sensitive body in diagnostics. Do not retry deterministic screening or unsupported-file failures. Retry transient I/O and busy outcomes with backoff and cap. Bound the persisted failure list to 50 on every write, and migrate a legacy 51-entry state before validation. Recovery must not lose a previously valid evidence record or silently reuse an invalid one.

## Workbench and live acceptance

Workbench selection consumes only valid screened excerpts and typed provenance. Explicit saved items remain primary; an activity signal alone never creates a card. Generated suggestions may be zero. When scanning is partial, the empty-state copy explains that authorized material is still being organized and never promises suggestions.

On the first software open, show saved records and previously valid, version-checked cards immediately; start the whole-computer scan in the background without gating navigation. Publish source-progress snapshots at most once every two seconds while scanning. A newly valid excerpt updates the eligible-candidate set without waiting for the complete computer crawl. Coalesce eligible changes: the first useful set may generate after a three-second quiet period, with a ten-second maximum wait after its first eligible change; later automatic generations wait for a thirty-second quiet period, with a two-minute maximum wait after the first change. The minimum two-minute spacing and six-per-hour limit take precedence over these maximum waits. Automatic calls run only when the top eligible candidate IDs or fingerprints materially change. Persist the last generated signature and rolling automatic-call timestamps with the card state, so restarting cannot repeat unchanged generation or reset the limit. When a call is rate limited, keep the changed signature scheduled for the next eligible time; do not lose it. Manual refresh does not consume the automatic six-per-hour quota, but it respects single-flight and provider concurrency limits. A newer change while generation is running is handled in the next coalesced pass. Progress counters alone never trigger model calls or broad personal discovery. Pause/disconnect/close cancels scheduled automatic work.

Invalidate stale evidence and derived cards promptly, before any debounce or model call. Saved Todos, Goals, news, task state, and confirmed profile records publish on their own existing paths. Source updates never auto-create those records or change the selected tab. The renderer applies a new snapshot only when its visible data changes and preserves the user's focused input, unsubmitted text, selection, and scroll position even on a material card update; scanning progress must not repeatedly replace card DOM. A failed/abstaining model leaves the page in its truthful empty or prior-valid state and retries with backoff rather than on every scan batch. The existing periodic proactive-discovery interval remains independent from source indexing and must not be reset or invoked per indexed file.

Acceptance has two gates. First, deterministic tests cover budget exhaustion, 50/51 failures, directory mutation during interruption, restart, deleted/unavailable roots, hidden paths and explicit exceptions, permissions, same-name changes, same-metadata content changes, watcher loss, fair scheduling, revocation, first-open background progress, coalesced generation rate, and stable focus/scroll while the active tab receives updates. Benchmarks compare time to first eligible evidence and bounded resource use against the current implementation on representative synthetic trees; do not claim a speedup without measurements.

Second, stop any other Nova process, verify the original profile lock is free, and make and verify an immutable recovery backup. Rehearse any required migration and rollback with synthetic profile fixtures; the backup is never mutated or used as acceptance input. Commit and build the candidate before the run. The normal native desktop entry point must assert, before opening data, that Electron `userData` matches the recorded original daily Electron directory and the runtime blackboard path separately matches the recorded original daily blackboard file; these are different paths. It must record the launcher, pre/post source state, profile hashes, and exact clean build commit. Quiescence means no immediately eligible scan item across consecutive scheduler checks; if a bounded wall-clock run ends first, report remaining items by reason and due time rather than claiming completion. Check actual source-to-excerpt-to-candidate-to-model-to-renderer counts, including valid zero-card cases, from the same process through a read-only diagnostic path. Capture every workbench page from the production native window using OS window capture or a read-only debug protocol; the old self-built BrowserWindow is not valid. Before startup, permit outbound processing only through the explicitly authorized Claude Opus 5.5 path or providers named by the original source's still-valid persisted processing grant; do not silently substitute a provider or widen a grant. Suppress unrelated news refresh, proactive discovery, and other external paths during acceptance, and log allowed and blocked calls. A disabled or mismatched embedding provider is a configuration failure, not a valid zero-candidate outcome. Store time-series diagnostics, screenshots, and reports at an explicit path outside the profile and public branch; do not reset or seed the original data. Do not run the old harness's profile-copy or context-deletion steps.

## Scope and compatibility

Implement inside the existing personal-source, knowledge, and desktop paths. Keep all new code and tests generic; do not embed local paths, credentials, organization data, or private pilot integrations in public source or commits. Do not merge into `main`, publish, or deploy as part of this specification. Preserve the dirty main checkout and unrelated worktrees. The previous isolated-copy screenshot harness remains historical evidence only and must not be labeled live acceptance.
