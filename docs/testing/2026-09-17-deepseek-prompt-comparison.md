# DeepSeek Flash：正式提示词与候选对照

> 最新决定：用户明确要求直接替换，现已将 V6 写入正式源码。系统提示词、dispatch 描述、级联每轮提示与已测 V6 逐字一致；模型选择和仅前台关闭 thinking 保持不变。下文“不替换”是此前的阶段性决定，已被本次授权取代；已知缺陷不因此视为修复。客户端尚未重启。

> 范围纠正：用户要求仅前台关闭 thinking。此前扩大到共享支持网关的改动已撤回，下游保持提供商/原有配置，前台关闭逻辑保留。下文 Thinking 覆盖补齐及其 live 结果是撤回前的历史记录，不代表当前实现。

本轮固定 18 场景 × 3 次，模型为 `deepseek-flash`，关闭思考。开始前保存 `v4-cases.json`，各候选使用相同用例与预期，未中途放宽判分。只有产物名称且没有相关用户上下文的新增游戏/工具用例要求相关澄清；不规定问题必须是平台。另有相关用户上下文、明确委托、明确任务、未决/已决删除边界等对照。

正式基线与 V4 同批执行；V5、V6、V7 后续分批执行。因此这是一轮小规模对照探索，不是随机盲测，不能把差异完全归因为某一条句子。未执行返回的工具，没有真实 Codex/工作区/审批/语音验收。

## 文案变化

以没有额外示例、且动作判分较好的 V6 为主要候选：

| 方面 | 正式提示词 | V6 |
| --- | --- | --- |
| 决策依据 | 判断能否开始，另有较宽泛的“多种实现交给执行器”表述 | 结合用户结果、使用方式、范围及已给出的上下文/委托判断；不把任务名称或目录名当作充分依据 |
| 澄清与工具关系 | “编程、项目和会话相关的请求一律只用三个宿主工具” | 讨论/澄清直接对话；决定操作后才用三个宿主工具 |
| 修改和验证 | 要求实现时必须要求实际修改、运行验证 | 明确限定在已经决定派发之后，不构成跳过澄清的理由 |
| 参数 | 要求保留约束，不添加技术栈 | 强调保留约束的强度和范围，不新增禁止项 |
| 解释事实 | 有通用事实边界要求 | 明确要求未知触发原因或历史说未知，不补写前情 |

均保留前台 dispatch/confirm/cancel 与下游 coordinator 的职责，没有新增分类器、关键词拦截、自动重试或工具权限变化。默认全功能系统提示长度从 5,830 字符变为 5,990，每轮固定提示从 466 变为 408；并非大幅精简，主要是语义调整。

## 参数和事实人工审阅

- “不用安装依赖”仍被收紧：正式基线 1 次明确禁用外部库/CDN，V6 1 次明确禁用外部库。不能声称修好了参数忠实度。
- V6 `holdout-workspace-only / repeat 0` 把“先不要写代码”扩写为“不进行文件创建或运行操作”。创建工作区可能需要初始化文件，这个新增限制应单独标记，不能因 dispatch 正确就忽略。
- V6 三次确认原因回答均承认没有触发原因的证据，没有补出某个先前用户请求；但部分口播仍长。这只是本批表现，不能保证稳定。
- V6 的裸游戏 3/3 直接派发，且相关上下文/委托并不存在。因此不能用总动作分改善掩盖关键缺口。

V7 的具体回归是将“把这个系统里的过期记录都删掉”直接 dispatch，要求下游先确认系统和过期规则再删除。此时前台已经把未澄清任务交下去了，违反既定职责；不是通过保留原话就能解决。

## 结论与证据

有局部改善，没有达到可替换正式版本的标准。**本轮不合入任何候选，不改变客户端当前提示词或模型**。停止继续累加句子、例外或针对单个测试名称打补丁。

证据目录 `.data/diagnostics/2026-09-17-prompt-review/`：`deepseek-v4-ab.json` 保存正式基线/V4；`deepseek-v5.json`、`deepseek-v6.json`、`deepseek-v7.json` 保存后续候选；各文件保存实际提示面及 `actualSurfaceHash`。已确认当前编译后的正式提示面与保存的 baseline 完全相同。`v4-fable-review.txt` 为本地 `claude-fable-5-1` 的只读评审，其观点经实际测试验证，并未直接作为通过结论。

## Thinking 覆盖补齐

前台级联 Qwen/DeepSeek 与 Ark 原本已显式关闭 thinking；此前共享支持网关只有 surrogate 的两个 Qwen 型号带关闭参数，coordinator/intake、planner、compressor 未统一覆盖。本轮将协议设置收敛到共享网关 POST，同时覆盖 complete/stream，移除 surrogate 的型号特判。

选定提供商的自定义端点沿用其明确协议；通用配置只识别已知官方主机，未知通用端点不额外传参数，不能保证其 thinking 关闭。没有修改 Codex 执行器的推理配置，也没有修改设置面板当前模型。

- 构建通过，网关、adapter、intake、级联模型与组合测试共 117 项通过。组合测试的两处旧 descriptor 预期已同步到已有的新建/切换工作区能力。
- 真实共享网关调用：DeepSeek Flash 发出 `thinking: {type: disabled}`，Qwen Plus 发出 `enable_thinking: false`，均返回预期 JSON，`reasoning_content` 为空。完整调用分别约 695ms / 468ms，仅单次连通性检查，不是 TTFT 或性能对比。
- 证据：私有诊断目录 `support-thinking-live.mjs` 与 `support-thinking-live.json`。未重启桌面客户端，不能据此声称当前运行进程已加载修复或完成麦克风/播报验收。

本地 Fable 的最终摘要评审指出需要区分动作分与参数审阅、补充真实流式检查。本报告上表已分别列出基线/V6 逐类结果，51/54 不包含参数忠实度得分；保留基线不是宣称基线合格。补做 DeepSeek Flash 真实 stream 请求通过，发出的 thinking 为 disabled，没有 reasoning chunk；同次重跑 complete 的 DeepSeek/Qwen Plus 也通过（约 585ms/481ms）。Ark 仅有请求协议测试，没有本轮 live 证据。评审文件为 `fable-final-verdict.txt`，它基于摘要而非完整代码审查。


## 对采用结论的纠正

V6 的已知游戏缺陷在基线中也存在，且“禁止外部库”的约束扩写在两者各出现一次；它们说明尚未完全达标，不能单独证明 V6 比基线差。V6 动作判分改善集中在模糊优化、倒计时、倒计时澄清多轮，其他 14 场景动作判分相同。V6 新观察到的工作区参数扩写需要配对复测；每场景 3 次且后续批次不同，不能据此证明稳定的回归概率。V7 则观察到未澄清删除范围就派发，应排除。

因此证据支持“V6 是有改善的候选，但尚不足以直接全量替换”，不支持“所有候选均劣于生产版”。保留基线仅是暂缓发布，下一步应围绕 V6 的参数忠实度、游戏澄清和明确任务不过度追问进行同批配对验证，不能靠继续堆规则或把基线称为合格来结束。
