## Observed failures and ownership

### Progress is delivered, but stale prose is presented as new progress

In the eager calculator control, task start was at 46.40 seconds, intermediate speech at 57.86 and 92.10 seconds, terminal result at 93.21 seconds and final speech at 98.02 seconds (probe-relative clock). Both intermediate decisions selected `routine_delta` with `suppressed=false`.

The second source summary concatenated command/file counters with the old future-tense plan. `runtime/src/executors/codex/turn-projection.ts`, `#composeSummary`, does exactly that. The frontend then said it had received task context and repeated the plan. This reproduces a concrete evidence-construction problem; switching models alone does not resolve it. Separate operational counters from genuinely new executor prose at this existing boundary, retain provenance/freshness, and verify repeated-plan versus actual-new-finding cases. Do not add keyword detectors or a forced narration timer.

### Listing files was narrated as creating files

Actual command: `ls -1A`, exit 0. Codex final text was only the four file names. `finalSpeechView` prefixed this with “Codex 报告任务完成”. Qwen Plus then said “生成了四个文件”. The narration claim is unsupported; the command itself succeeded.

The handoff projection lacks explicit operation context in this terse final message. Inspect the correlated task/result context before choosing the smallest repair; do not infer a zero change count from absent evidence, and do not post-process “生成” into another verb. Acceptance must distinguish listing existing artifacts from creating artifacts.

### Workspace interpretation still needs investigation

The vague-current-workspace case became a create proposal despite persisted active workspace state. The explicit-existing-workspace control worked. This establishes a routing discrepancy, not its full cause: inspect the exact coordinator input and startup active-binding projection before changing prompts or authority rules. Preserve frontend dispatch/confirm/cancel and downstream workspace/session decisions.

### Audio segmentation has two distinct issues

The initial Electron test process resolved capability fixtures under the development Electron Resources directory, where they do not exist. Built fixtures exist in `clients/desktop/build/endpointing/volcengine-v1`. `loadCapabilityFixtures` selects only the Resources path when it is present, so that probe reported `bounded_silence/inconclusive`.

A read-only probe with the built Resources path reached `livekit_v1_mini`, EOT ready and VAD ready. A subsequent same-text synthetic speech control using those resources still split the request into two accepted transcripts: workspace creation, then file/content/constraints. Exact identifiers were also misrecognized. Thus missing fixtures explain the initial downgrade but do not fully explain premature turn commitment. TTS was synthesized again, so this is a same-text control, not a bit-identical audio replay.

The corrected control also emitted `cascaded_response_failed` and reconnected. Its provider-idle completion is not proof of a successfully answered request. Retain this failure separately. Do not infer the running desktop client's endpointing mode from the development harness, and do not fix this by guessing a larger silence delay.

## Review and remaining release gates

Local Claude CLI with `claude-fable-5-1` reviewed the synthetic evidence. Its useful recommendation was to preserve action meaning and unknown states at data boundaries. Its suggestion to assert zero modified files when no write evidence exists was not adopted; absence of evidence is not zero. A second Claude discussion recommended splitting intent from activity. This remains a proposal, not an implemented or accepted design: assistant prose can contain findings, not just intent, and command names do not reliably establish read/write semantics. Its claim that the client has no fault was rejected as unsupported; the resource-corrected long-utterance control still failed. No suggested architectural rewrite was implemented.

Remaining gates: accurate non-repetitive progress/result narration; current-workspace routing; semantic turn boundary and provider interruption recovery; actual browser/approval bridge execution; physical microphone/speaker and running-client UI acceptance. Previous renderer checks and synthetic approval tests remain separate evidence, not substitutes for these gates.
