# Mobile Timeline quality and history retention

## Intended behavior

Mobile Timeline follows desktop relevance rules: show matters that affect the user, merge plans with later completion/cancellation across dates, and omit routine notifications without a concrete personal consequence. There is no target card count. No worthwhile new item is a successful empty assessment, not a request to erase previous results.

## Processing

Use validated observations as a selection index across the available history. Retrieve complete original messages for each selected matter, admit whole groups within the existing input limits, then draft, review and edit with the originals. Observation summaries never become final evidence. Each card contains a title, supported facts with exact quotes, a reason the change matters, optional next steps and material uncertainty. Source timestamps remain source timestamps. Suggestions never create tasks or send messages.

Keep Profile sampling and Timeline selection distinct. Restore and validate nested citations before publication. Retain prior successful Profile categories and Timeline independently when a new assessment has nothing to replace them. Source deletion, expiry, day changes and processing errors do not remove saved results; account and space isolation still apply. Explicit deletion remains separate.

## Presentation

Show concise matter cards, with source dates and original-message links below the content. Preserve old text-only cards. Move detailed processing counts into expandable coverage information. No next-step section when no useful action exists. Retained history remains visible without repeatedly scheduling already-expired source timers.

## Validation

Exercise global topic grouping, complete-original limits, irrelevant/empty output, quote and citation validation, independent section retention, account isolation, legacy mixed history, missing originals and narrow screens with enlarged text. Run the Flutter suite and analyzer, then build on the isolated external volume. Real generated-content quality requires a separate budgeted device run; fixture tests cannot establish it.
