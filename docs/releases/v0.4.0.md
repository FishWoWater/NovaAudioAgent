# Nova Personal Agent v0.4.0

Nova 0.4.0 keeps your conversation, context and ongoing work together.

- **Persistent home and Timeline:** keep Nova beside a tabbed workspace, with context, evidence and task results available to revisit.
- **Scheduled Agent Tasks:** run work once, daily or weekly, manage schedules on desktop or mobile, and receive reports in the main conversation. Task definitions and recovery state persist across restarts.
- **Incremental sources and Profile:** sync authorized sources incrementally and resume background processing. Profile writing now focuses on understanding the person, retaining evidence for correction and source withdrawal.
- **More coding backends:** choose Codex, OpenCode, CodeBuddy, Pi or DeepSeek Harness. Sessions retain their backend, with improved ACP failure recovery and native Windows launching.
- **Guarded specialist execution:** browser, computer and phone executors share approval, cancellation, screenshot evidence and result verification. These GUI/device paths remain experimental.

## Install

Requires Node.js 22.13+ for the desktop launcher; the Ubuntu headless server requires Node.js 22.14+.

```sh
npm install --global nova-personal-agent@latest
novapersonal
```

Headless Ubuntu 22.04+ x64: `npm install --global nova-personal-agent-server@latest`.

The old `nova-audio-agent` npm entry receives the same 0.4.0 launcher and refreshed documentation. To switch names, first uninstall the old package to avoid command-link collisions. `novaaudio` remains a command alias, and existing user data/settings stay in place. Do not install both desktop package names together.

## Boundaries

Profile summaries are model-generated and need reference checks. Default message ingestion remains your own messages and direct mentions; this release does not automatically include all collaborators' messages. ACP permissions differ from Codex, Pi has no per-action approval, and live steering remains a Codex feature. GUI/phone execution and configurable Feishu outbound delivery require environment-specific setup and are not universally device-validated. Scheduled task creation through conversation depends on the configured model; schedules can also be managed directly in the client.
