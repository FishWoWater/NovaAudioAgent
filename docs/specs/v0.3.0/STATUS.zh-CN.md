## 2026-09-21 新增上线要求：广覆盖个人上下文（部分实现）

正式产品应在用户授权范围内覆盖多个项目目录、文档与笔记、论文资料、创作素材、下载目录和外接盘；不能以当前仓库的少量文档代替整体画像。取样需兼顾来源与主题，区分活跃项目、历史积累、外部收藏和生活事务，并展示遗漏与不可访问范围。副本、工作树、生成文件数量不得直接放大兴趣权重；旧待办不得自动升为当前承诺。上线前增加来源失衡、重复副本、过期证据、外接盘离线与撤权等验收。详见 [广覆盖产品要求及验收条件](CONTINUATION-IMPLEMENTATION.md#product-requirement-broad-personal-context-coverage-2026-09-21)。已于 09-22 实现下述有界取样与 RSS 语言路由；整体画像质量与完整覆盖仍未验收。

深度与广度同时验收：以逻辑项目或资料集合分配注意力，Git 仓库先作为一个单元理解定位、结构与状态，不因文件多而持续占用取样预算；遇到任务需要、关键未知或矛盾证据再深入。单仓多项目、同项目多副本及非 Git 资料库需保留真实边界。加入“给单仓增加大量冗余文件，其他项目仍能被发现”的用例，同时保留需要深入理解单项目的用例。

## 2026-09-22 项目取样与 RSS 语言路由

先使用本地 Claude CLI `claude-fable-5-1` 讨论设计，再实现及验证。Git 目录或工作树标记建立项目边界；项目间轮流读取，单个 Git 项目最多选 8 份代表文档，根 README 优先于嵌套 README；单项目元数据预算 2,000、单授权根总预算 20,000。非 Git 子目录按资料集合轮流取样，继续受授权根的文件与字节预算限制。重复同步不会无变化地读完整个 Git 项目；非 README 文档可进入带来源的观察。来源快照跨根轮流取证并按内容指纹去重，主机不会被其他证据挤掉全部本地来源。

RSS 在后台启动时使用操作系统首选语言，独立于保存的界面语言：中文系统只用中文源，其余只用英文源，失败不会跨语言补源。切换系统语言后需重启后台；旧语言缓存和收藏从当前视图隐藏，收藏仍持久保留，切回可恢复。不会自动翻译外文充作中文源。

实际目录运行已发现并记录元数据上限和入库失败；不将取样成功称为整机覆盖。去重仅作用于证据快照，没有合并不同项目，也不据文件数量推断兴趣或身份。任务驱动的自动深入、跨授权根的全局容量分配、语义项目合并和画像质量仍待后续验收；Knowledge 的默认 100 源容量上限仍保留。

## 授权后真实模型验收

用户明确允许将选定的七份 README 节选发往已有阿里云 Qwen 服务。验收复用桌面 safeStorage，不记录密钥；输入、输出和临时数据库保留于忽略的本地目录。

- 实测发现原适配层只发 JSON mode，没有传递 schema；摘要调用现在显式把 schema 放入模型可见请求。
- 单次自由归纳出现遗漏、上游成果误归属、虚构集成关系。改为两步：逐条提取核心事实并校验 ID/version 一一对应；再分组、生成标题/关键词/总览。卡片正文按分组拼接已提取事实，模型不能只补引用却漏掉正文。缺项、重复、错版本、超长或失败均回退，最多两次调用，共用主机 30 秒期限。
- Qwen Plus 最终样本：七条主题全部进入正文，四张卡片，每卡最多三个关键词；两次请求合计 26.9 秒。分支工作、上游归属、演示方案及不同项目关系经独立 review 通过。实际 renderer 已显示原始模型结果，默认无依据/来源入口。
- 默认 Qwen Flash 在本样本中表现不稳定，多次未通过结构或内容验收；Plus 对照通过不代表 Flash 通过，也不代表长期生成质量已保证。未修改全局或持久模型配置。
- 当前摘要回归 10/10，编译、相关 lint、Node parity 检查通过。界面目标验收通过；端到端已安装客户端、默认 Flash 质量和更广样本验收仍分别记录，不据此宣称发布就绪。
