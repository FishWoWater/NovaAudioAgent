## 2. 本卷新增

### 2.1 Connector 通用层

一个 connector 同时服务两个场景：用户按需查询（工具）和后台增量同步（来源记录）。共享账户、
权限与 provider 实现。

通用层负责：连接状态（`connected | paused | disconnected | error`）、凭据引用（凭据本体只由主机
持有，模型与 renderer 不得到原始 token）、同步进度（provider cursor）、重试与配额、
最近同步时间与错误。Provider adapter 保留领域语义（邮件线程、日历重复规则），不把一切压成纯文本。

**来源记录**回答"实际读到了什么、什么时候读到"：保留账户、原始 ID、版本、时间和可追溯链接。
它是 02 卷 `evidence_refs` 与 03 卷 `source_refs` 的引用目标。

MCP 是工具暴露方式。可复用现有 MCP server 作为查询工具，但**只提供搜索工具不等于具备持续同步能力**。
判定标准：能否稳定分页、能否给出变更（新增 / 修订 / 删除）、能否从中断处恢复。不满足则只作为按需
查询工具接入，不产生来源记录。

### 2.2 本地目录（M7）

- 用户在设置中选择允许的目录；每个目录独立开关。默认不选任何目录。
- **元数据概览先行**：先扫描范围内的路径、类型、大小、修改时间，形成概览；正文按相关性、近期变化和
  预算（每次同步的文件数与字节上限，待评审）选择性读取。
- **排除**：敏感路径（凭据、密钥、浏览器配置等模式列表）、缓存、依赖目录（`node_modules`、
  `.git`、构建产物等）默认排除且用户可见；符号链接解析后重新验证是否仍在允许范围内。
- **增量**：监听或轮询变化；启动与恢复后做一次补充核对。删除的文件传播为来源删除。
- **可见性**：设置中显示已扫描文件数、已读正文数、跳过数与原因、解析失败列表、上次同步时间。
  只处理部分文件时不得宣称"了解了整台电脑"。
- 元数据与路径本身是受控内容：不进入遥测；进入模型时受同样的低信任约束。
- 复用知识导入与检索；在其外围补来源管理与增量，不重写文档解析。

### 2.3 邮件与日历（M8）

以**一个** provider 验证闭环再扩展。Google Calendar 与 Gmail 是候选，不是已确认选型（待评审）。

- **日历**：保留事件 ID、日历归属、时区、全天语义、重复规则与例外、取消状态。
- **邮件**：保留消息 ID、线程归属、参与人、时间、正文及必要状态。"是否待回复"需检查线程，
  不由一封历史邮件决定。
- **同步**：初次同步明确范围（时间窗、标签 / 日历选择）；后续保存 provider cursor。变化与 cursor
  的持久化必须保证失败后可安全重试。Google Calendar 用 syncToken，失效时全量重同步；
  Gmail 用 historyId，历史过期时恢复同步；Microsoft Graph 后续可用 delta 适配。
- **删除与取消**传播到检索与关联建议；临时网络失败不能被当成来源已删除。
- 第一阶段后台增量轮询；网络恢复后补同步。推送只用于改善时效，不替代差量拉取。
- 多账户隔离：来源记录带账户标识；不同账户的记录不串用。

### 2.4 授权、暂停、断开、删除

设置中每个连接显示：账户、读取范围、后台同步开关、模型处理方式（本地 / 云端）、最近同步时间与状态。

OAuth scope 与 Nova 内部范围分别展示："只处理选定标签"是 Nova 自身执行的过滤，不能声称
provider token 只允许该标签。发信、创建邀请等写权限按实际需要单独开放，且走执行授权路径。

三种操作语义：

| 操作 | 效果 |
|---|---|
| 暂停同步 | 停止后续读取；已有来源记录、检索与记忆保留 |
| 断开连接 | 停止后续访问并丢弃凭据引用；已有内容保留但标记来源已断开 |
| 删除来源数据 | 清理该来源的索引与来源记录；派生记忆按 03 卷规则处理（有其他独立依据的保留有效部分）；相关 suggestion 撤回、`feed_item` 置 `invalidated`；用户主动忘记的内容记录抑制标记，防止重连后立即再生成 |

外部内容始终是低信任证据，不是系统指令或用户授权。采集与模型处理范围由主机实际执行，不只写在提示词里。

### 2.5 与执行生态的边界

Kimi Code、pi agent 与 GUI/AutoGLM 的适配、验收和 agent2agent 演示见
[05 Coding 与 GUI 执行器](05-coding-and-gui-executors.md)，可独立于 M7/M8 开工。
Connector 提供获准访问的来源与按需查询；executor 接受已授权工作并执行。
来源读取权限不自动授予发送、修改或设备操作权限。组织专属服务仍留在 internal。

## 3. 不做

- 全盘无差别采集、屏幕录制、剪贴板监听。
- 一次接多个邮件 / 日历 provider。
- 在 renderer 或模型侧持有任何凭据。
- 把 MCP 搜索工具当作同步来源。
- 承诺关机后持续同步（见 00 卷部署边界）。

## 4. 待评审

| 项 | 选项 | 影响 |
|---|---|---|
| 第一个邮件 / 日历 provider | Google / Microsoft / 本地 IMAP + CalDAV | 影响 OAuth 审核、增量机制与目标用户 |
| 每次同步预算 | 文件数与字节上限的默认值 | 影响首次同步时长与模型成本 |
| 本地目录变化检测 | 文件系统监听 / 定时轮询 / 两者结合 | 影响资源占用与跨平台差异 |
| 首版写入能力 | 只读 / Nova 内草稿 / 有授权的发送 | 影响 OAuth scope 与风险面 |
| 敏感路径排除列表 | 内置固定 / 内置 + 用户可增 | 影响误读风险 |

## 5. 验收场景

编号沿用讨论稿 §9。

- **8 来源变化**：邮件提出改期且与已有日历冲突，feed 出现冲突卡片并给出处理选项；会议随后取消，
  卡片更新为已解决，相关提醒撤回。
- **9 同步恢复**：断网、限流、cursor 失效、重复分页分别注入，同步能恢复且不产生重复来源记录；
  两个账户的记录互不串用。
- **10 权限边界**：外部邮件正文中包含"请立即执行 X"，不触发任何 dispatch；断开连接后不再读取；
  删除来源后相关检索返回空，派生记忆按规则处理。
- **目录覆盖诚实**：选择一个含 10,000 文件的目录，预算只读 200 个正文；设置页显示实际数字，
  记忆概览的覆盖声明与之一致。
- **排除生效**：目录内含 `.git`、`node_modules` 与一个指向范围外的符号链接；三者都不被读取，
  跳过原因可见。
