# 01 邮件与日历（M8）

状态：规划，未实现、未验收。2026-09-11 从 v0.3.0 移至 v0.4.0，保留 M8 编号。

依赖 v0.3.0 M7 的来源记录、记忆传播和 feed 契约；不阻塞 M9 执行器。


以**一个** provider 验证闭环再扩展。Google Calendar 与 Gmail 是候选，不是已确认选型（待评审）。

- **日历**：保留事件 ID、日历归属、时区、全天语义、重复规则与例外、取消状态。
- **邮件**：保留消息 ID、线程归属、参与人、时间、正文及必要状态。"是否待回复"需检查线程，
  不由一封历史邮件决定。
- **同步**：初次同步明确范围（时间窗、标签 / 日历选择）；后续保存 provider cursor。变化与 cursor
  的持久化必须保证失败后可安全重试。Google Calendar 用 syncToken，失效时全量重同步；
  Gmail 用 historyId，历史过期时恢复同步；Microsoft Graph 后续可用 delta 适配。
- **删除与取消**传播到检索与关联建议；临时网络失败不能被当成来源已删除。
- 第一阶段后台增量轮询；网络恢复后补同步。推送只用于改善时效，不替代差量拉取。
- 多账户隔离：来源记录带账户标识；不同账户的记录不串用。


## 权限与生命周期

沿用 [来源生命周期](../v0.3.0/04-sources-and-connectors.md)：暂停保留内容，断开停止访问，删除传播到检索、记忆、建议。OAuth scope 与 Nova 内部范围分别展示；凭据只由主机管理；邮件正文不是执行授权。
