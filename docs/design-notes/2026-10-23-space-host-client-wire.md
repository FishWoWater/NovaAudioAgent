# Space wire v1 (implementation contract, 2026-10-23)

This is an implementation specification, not an external cryptographic review. TLS is mandatory outside explicit loopback development. Relay sees public identity, membership, epochs, routing metadata and ciphertext. Relay never receives identity private keys or Space content keys.

## Identity and JOSE

Device identity: Ed25519 signing JWK (`kty=OKP, crv=Ed25519, x`), and independent P-256 agreement JWK (`kty=EC, crv=P-256, x,y`). Private JWKs are persisted only on endpoints in permission-restricted storage (platform Keychain/Keystore preferred). `space` is the RFC 7638 SHA-256 thumbprint of the initial Host signing public JWK. This Host is immutable for that Space. `device` is an opaque random identifier. Identity keys are generated independently per Space. No automatic Host replacement or takeover.

`body`: standard padded base64 of UTF-8 compact JWE, protected header `{alg:"dir",enc:"A256GCM"}`. For initial key distribution and rotation, `body` instead contains base64 of the recipient-specific ECDH JWE described below; the same outer Host JWS is mandatory. Content key is 32 random bytes, generated and retained by Host. Plaintext is UTF-8 JSON. Endpoint key delivery uses compact JWE `{alg:"ECDH-ES+A256KW",enc:"A256GCM"}` with recipient P-256 public key. Key-delivery plaintext binds `{v:1,space,epoch,recipient,key}` (`key` base64url). Key delivery must be Host signed and verified against QR-pinned Host signing key before installing; never accept unsigned wrapped keys from Relay. A fresh content key is required on epoch change, delivered independently to each remaining device. Envelopes for content at an epoch cannot be sent before that epoch's key is installed.

`sig`: standard padded base64 of UTF-8 compact JWS, protected header `{alg:"EdDSA",typ:"nova-envelope+jws"}`. Payload is exact UTF-8 `JSON.stringify` of fields in this order (no whitespace): `{v,space,id,from,to,chan,epoch,expiresAt,body}`. All IDs are ASCII `[A-Za-z0-9_-]{1,200}`, numeric times/epochs are safe integers, `expiresAt` is milliseconds or null. Verify exact bytes, protected alg/type, signature and current sender membership. JOSE implementations produce unpadded base64url inside compact serialization; outer body/sig use padded standard base64 to preserve existing mailbox contract. Never sign a map in unspecified order.

## SecurityStore adapter (relay/src/security.ts)

- `new SecurityStore(sqlitePath,{bootstrapToken,now?})`; implements synchronous `RelayAuthority`; `close()`.
- `createSpace({space,host:{device,signingPublicKey,encryptionPublicKey},proof},bootstrapToken)` -> `{space,host,epoch:1}`. Bootstrap token is an operator deployment secret, compared in constant time. Creation proof is raw compact EdDSA JWS, typ `nova-control+jws`, with JSON payload `{v:1,purpose:"space-create",space,host:{device,signingPublicKey,encryptionPublicKey}}` in exactly that insertion order. Host signing key thumbprint must equal Space. Creation is insert-only, never overwrites.
- `getSpace(space)` -> `{space,host,epoch}`; `listDevices(principal)` -> public active device records.
- `beginLogin(space,device)` -> `{id,nonce,space,device,epoch,expiresAt}`; challenge expires in 60 seconds and is single-use. Unknown device fails.
- `completeLogin({challengeId,proof})` -> `{token,principal:{space,device,epoch},expiresAt,selected_version}`. The selected version is the confirmed member version, mandatory for endpoint session validation. Proof is raw compact JWS typ `nova-control+jws`, payload `{v:1,purpose:"relay-login",challengeId,nonce,space,device,epoch,expiresAt}`. Exact values from challenge. Challenge is atomically consumed on success. Opaque 256-bit session bearer tokens expire after 15 minutes; only token hashes are stored. Current membership and epoch are checked on every request.
- `authenticate(authorizationHeader)` -> principal. Only `Bearer <token>` accepted. Never infer principal from JSON or URL. Sessions survive restart; epoch transitions invalidate all old sessions.

## PairingStore adapter (relay/src/pairing.ts)

`new PairingStore(security)` wraps SecurityStore's same methods:

- `createInvitation(host,{ttlMs?}={})` -> `{id,space,secret,expiresAt,host,hostSigningPublicKey,business_versions}`. Default 5 min, max 10 min. QR contains these plus trusted Relay URL; it must never contain content/private keys.
- `requestPairing({invitationId,secret,device,signingPublicKey,encryptionPublicKey,business_versions,proof})` -> pending `{id,space,device,signingPublicKey,encryptionPublicKey,expiresAt,fingerprint,business_versions,selected_version}`. Invitation is consumed atomically by one device claim, even before confirmation. An identical valid signed claim may replay its durable public response until expiry; a different claim for the same invitation is rejected. Only the payload digest and public response are retained, never the raw secret or possession proof. Proof: raw compact JWS `nova-control+jws`, exact JSON `{v:1,purpose:"pair-request",invitationId,secret,device,signingPublicKey,encryptionPublicKey,business_versions}` signed by requesting device. `business_versions` is a mandatory bounded unique array of positive integer versions. The invitation advertises Host-supported versions (currently `[1]`); Relay selects the highest supported intersection and rejects an empty intersection with `unsupported_business_version`. Pending and confirmed records persist `business_versions` and `selected_version`, and login returns the selected version. Relay stores only hash of secret. Pending device cannot authenticate or receive mailbox messages.
- `pendingPairings(host)` -> pending unexpired requests, key-pair fingerprints. Host UI must obtain explicit user confirmation comparing fingerprint with Client screen. `deviceFingerprint(signing,encryption)` is base64url(SHA-256(UTF-8 JSON.stringify({signing:{crv:"Ed25519",kty:"OKP",x},encryption:{crv:"P-256",kty:"EC",x,y}}))), with exactly that property order. It binds both keys. Host must durably retain the approved key pair locally; Relay device lists are discovery, not trusted key replacement. This prevents a compromised Relay from replacing the agreement public key while retaining the signing fingerprint.
- `confirmPairing(host,requestId,opId)` -> DeviceRecord. Only immutable Host, current epoch, unexpired pending request. This is admission only; Host then delivers fresh Space key with standard encrypted/signed key delivery. No content key supplied to Relay.
- `revokeDevice(host,device,opId)` -> `{epoch,remainingDevices}`. Host cannot revoke itself. In one transaction mark device revoked, increment global Space epoch, invalidate all invites/pending requests/challenges/sessions for Space. All old epoch reads/ACK/send are rejected immediately. Host then reauthenticates at new epoch, generates a fresh key and distributes only to returned devices. If key distribution fails, pause content traffic; do not reuse old key. Historical ciphertext already possessed by a revoked device cannot be withdrawn.

Confirmation and revocation require a durable endpoint-generated `opId` (HTTP `{requestId,opId}` / `{device,opId}`). Their SQLite transactions atomically persist both membership changes and public operation receipts. Retry the same operation with the same ID after a lost response; it returns the original result without a second admission or epoch increment. Reusing an ID for another kind/target fails `op_conflict`. Replaying a receipt after a later epoch transition fails `stale_control_receipt`, rather than installing obsolete membership. The Host journals pending confirmation/revocation and fresh key material before network calls, reauthenticates after epoch changes, and resumes the same operation ID. Control receipts fail closed at their configured finite history capacity.

This pre-release schema requires fresh security state when replacing an earlier delivery-only/prototype database; there is no legacy-state migration. Never delete deployed replay history in place to reset quota.

HTTP routes are adapter-owned. Protected endpoints call `authenticate` first; errors are `RelayError(code)`. Bootstrap create uses a distinct deployment-token header/body argument, never the device bearer. Pair request is authorized by single-use QR secret + possession proof; it is not an active session. Login challenge/proof and pairing endpoints must have source/global rate limits and body limits at HTTP boundary. Pairing status should be visible only to authenticated Host; devices authenticate after confirmation using their known Space/device ID.

## Endpoint helpers (relay/src/crypto.ts)

`generateDeviceIdentity()`, `spaceId(signingPublicKey)`, `signControl(payload,privateJwk)`, `verifyControl(proof,publicJwk)`, `signEnvelope(unsigned,privateJwk)`, `verifyEnvelope(envelope,publicJwk)`, `encryptBody(value,key)`, `decryptBody(body,key)`, `wrapContentKey({space,epoch,recipient,key},recipientPublicJwk)`, `unwrapContentKey(jwe,privateJwk)`. JWK helpers accept/return standard JWK objects; content key is Uint8Array(32). Endpoint persistence helpers save/load private identity with mode 0600 and atomic rename. Do not use endpoint persistence from Relay service.

Replay defenses depend on durable SQLite security state and trustworthy monotonic wall time. Relay compromise can deny service, reveal metadata or substitute unauthenticated discovery, but QR-pinned Host identity and verified endpoint signatures prevent content-key substitution. Forward secrecy for compromised historical shared content keys is not claimed. Operator bootstrap token distribution, endpoint OS secure storage, endpoint fingerprint UX and independent external crypto review remain deployment/release responsibilities.

## HTTP route contract

Bootstrap: `POST /v1/spaces` (`Authorization: Bearer <deployment-token>`). Public possession flows: `POST /v1/auth/challenge`, `POST /v1/auth/session`, `POST /v1/pairing/requests`. Authenticated: `GET /v1/mailbox?after=&limit=`, `POST /v1/mailbox`, `POST /v1/mailbox/ack {cursor}`, `GET /v1/mailbox/status`, `GET /v1/presence?device=`, `POST /v1/stream`, WebSocket upgrade `GET /v1/live`, `POST /v1/pairing/invitations`, `GET /v1/pairing/requests`, `POST /v1/pairing/confirm {requestId}`, `POST /v1/devices/revoke {device}`, `GET /v1/devices`. Device bearer credentials belong in HTTP/WS Authorization headers, never query strings.

The implementation currently limits JWS compact serialization to 256 KiB; service defaults are 512 KiB total mailbox envelope and 768 KiB HTTP body. Embedded full JWS payload amplifies ciphertext size; a 96 KiB binary camera fixture fits these budgets. Larger tools must resize or use a separately reviewed attachment protocol rather than silently increasing memory limits.

Fixed cross-language vectors are in `relay/test/fixtures/jose-v1.json` (all private keys are TEST ONLY). `jose-v1.ts` is the same vector for emitted TS tests. External cryptography review and device OS key isolation remain release gates.
