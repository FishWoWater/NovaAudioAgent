# 记忆系统参考对照与架构收敛（2026-09-12）

> 背景：v0.3.0 把 Nova 定位为有持续记忆、能发现需求的通用个人 Agent。本文记录 2026-09-12 对
> mem0、VoiceMem、OpenClaw、today.ai、mycontext 五个参考系统的对照，以及为什么没有采用
> "四个项目各占一层"的方案，而收敛为"三个架构层 + 记忆层内部三阶段"。契约见
> [06 记忆底座](../specs/v0.3.0/06-memory-substrate.md)。本文是背景，不是契约。

## 1. 五个参考系统

| 系统 | 记忆从哪来 | 记忆长什么样 | 吸收什么 | 不照搬什么 |
|---|---|---|---|---|
| mem0 | 对话轮次 | LLM 抽取的事实句 + 向量检索，可选实体关系图 | 写入动作集合：抽取候选后与旧记忆比对，决定 ADD / UPDATE / DELETE / NOOP。落在 06 卷 §4 的 merge 纯函数 | 作为依赖引入（Python + 向量库，与 Node-only 决定冲突）；事实无出处、不能逐条纠正。若其写入已改为只追加加读时归并，它做的是 A + C，跳过了显式修订 B；Nova 需要 B 是因为记忆页要展示"哪次修订、被谁纠正" |
| VoiceMem | 对话轮次 | 左脑事实 + 右脑情绪 / 风格，输出回复偏好 | 已接入，是 human-centric kind 的骨架；原生 TS 双脑设计（`docs/superpowers/specs/2026-09-05-native-ts-memory-design.md`）是其候选替代 | 当前命中无稳定 ID、无 origin、无列表；改为 B 阶段写入方而不是独立为真 |
| OpenClaw | 对话 + 心跳定时检查 | 人可读 markdown 文件，agent 自己维护，可被用户直接编辑 | 渠道无关的投递（IM bot 既是来源也是出口）；heartbeat 对应 02 卷 `tick`；记忆对用户可编辑对应 03 卷纠正 | 自由文本记忆规模上去后不能逐条纠正、去重；与 D3 结构化条目相悖 |
| today.ai | 遍历授权目录 | 关键词、标签、核心事项，最终一段画像 | "工作重心"信号：哪些项目热、哪些截止日期、哪些人。落为 06 卷 `topic` kind 与 M7 本地目录来源 | 画像式叙事（D3 已拒）；"了解整台电脑"的承诺（00 卷 Non-goals） |
| mycontext | 工作记录 | 数据库为真、三态合并、用户来源优先、agent 输出不入库、来源撤回级联 | 全部作为 A → B 的不变量，已在 workspace-graph spec 的 Design rules 中 | 它解决可追溯，不解决需求发现；不是一层 |

## 2. 被否掉的方案："四个项目各占一层"

起初的思路：mem0 做底层技术支撑，VoiceMem 做 human-centric 长期记忆，today.ai 式做
work-centric 层级，mycontext 打通关联与追溯。否掉的理由：

- 层与层重叠：mem0 与 VoiceMem 都是"对话 → 事实"；today.ai、mycontext 与现有 Workspace Graph
  都是"工作上下文"。仓库已有三套互不打通的记忆，再叠只会更散。
- "有迹可循"不是层，是属性。单独立层意味着一层存另一层的指针，两层永远分不开。
- 产品力不来自层数。可辩护的差异点只有一个：**每条主动提醒能指出证据，每条记忆能被纠正，
  纠正传播到待发的提醒**。这已在 02 / 03 卷里，只是没被当主线。

## 3. 收敛后的模型

三个架构层：来源 → 记忆 → 表现。记忆层内部按**数据变更方式**分三阶段，每阶段一种变更模型：

| 阶段 | 变更模型 | 一句话 |
|---|---|---|
| A 账本 | 只追加 | 归一化观测，存原文，来源断开物理删除 |
| B 条目 | 只追加的修订日志 | `memory_entry` 的修订；merge 是唯一写入口；用户纠正与模型合并是同一种记录 |
| C 视图 | 只读重算 | fold 当前态；回复偏好 / 回忆 / proposal 候选 / 记忆页四种投影；发布快照 |

两个视角（human-centric / work-centric）是 B 阶段的 kind，通过共享 `entity` 条目关联，不是两个库。
Discovery 拆两半：入库时抽取（A → B），tick 时筛选（C → 02 卷）。

同日的两个决策变更：
- 先定"A 不存原文"，后改为**存原文**。代价换成三项义务：字段级敏感策略成硬要求；来源断开物理删除
  原文行；保留期成为连接器配置。收益是换模型后可对账本重抽取，不必回来源重同步。
- 用户纠正与 merge 写入用**同一种修订记录**，只靠 `written_by` / `origin` 区分。同事架构图把
  "用户纠正"与语音、文字并列为输入，与此一致。

## 4. 与同事架构图（"Nova v0.3 · 持续理解与主动帮助"）的对齐

一致的四处：

1. "共同依据：来源 · 时间 · 作用域" = 可追溯是属性。
2. "明确表达 / 推断 / 更新 / 纠正 / 忘记" = B 阶段的动词集合。
3. "两个视角，关联同一份事实" = 同一张修订表上的两类 kind。
4. 底部回环"用户反馈与真实结果，持续修正理解" + 顶部把用户纠正列为输入 = 纠正是证据。

需要补的三处：

1. **账本没画出来。** "共同依据"作为一行文字容易被实现成条目上的三个字段；不存原文、断开级联、
   游标重放都要求一张独立的只追加观测表。
2. **"有时效的个人状态"** 需要 `valid_until` 字段，原三阶段模型漏了，已补进 06 卷。
3. **左右双向箭头要落到实体。** 否则两个视角各建各的"张三"。

一处冲突：**Discovery 的位置。** 图把它放在 Memory 之后；承诺实际是在消息入库时抽出的。
已拆为"发现即抽取"（Memory 框内）与"发现即筛选"（帮助层）。

改图意见（可直接转给作图者）：

1. Memory 框底部加一条独立横带"证据账本：原文 · 来源 · 时间 · 作用域 · 只追加"。
2. Discovery 拆两框：Memory 框内加"发现即抽取：承诺 · 等待 · 需求"；下层原框改名"发现即筛选：此刻值得提的"，指向 Proactive。
3. 动词带末尾加"重抽取"。
4. 双向箭头标注"共享实体：人 · 项目"。
5. 左侧"IM 渠道 · 近期切入"改为"IM 渠道（飞书）· M8-IM"；"邮件"标"M8-Mail"；虚线加小字"可配置保留期"。
6. 右侧"任务与工具结果"加限定"仅可核验的产物"。
7. 可选：Proactive 旁标"飞书 bot 也是投递渠道"，与 feed / 通知 / 语音并列。

## 5. 对现有 spec 的影响

- 03 卷"不新建第三套记忆存储"改为"不在 06 卷底座之外新建存储"；`memory_entry` 明确为 B / C 的投影。
- 02 卷的 Discovery 只指筛选；`memory_refs` 指向 `entry_id@revision`；`commitment` 方向映射到
  `notify` / `followup`。
- 04 卷连接器只产 `evidence_record`；删除来源 = 物理删除账本行 + 级联墓碑；新增 IM 连接器（飞书）
  作为来源与投递渠道，v0.3.0 范围内。
- 00 卷新增 D8；STATUS 新增"记忆底座"里程碑，M8 拆为 M8-Mail 与 M8-IM。
