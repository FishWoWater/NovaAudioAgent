## Context

实测（git 跟踪文件，不含 thirdparty/node_modules）：生产侧 115,378 行（含 desktop scripts 11k、native 4k、webui、ios），测试侧 121,261 行。竞品 qwen-audio-agent 约 50k / 40k。六路只读审计的共同结论：**几乎没有死代码**，臃肿来自四种习惯：

1. 每个内部接缝都当成对抗性信任边界，各自手写防御（native C 文件锁/inode 校验、进程 env 快照、store 自校验、Codex schema 手工重推导）。
2. 同一概念多层重复实现（"等人类决策" 4 套；desktop 传输 4–5 层；4 个子系统各自一套 worker/client RPC）。
3. 迁移期/发布期的验证工具长期留存（Python 对齐审计 JSON 5k 行、oracle 测试已在挂、发布验签/attestation/包检查脚本 6.3k 行 + 其测试 5.2k 行）。
4. 测试无共享 harness（realtime-service.test.ts 11k 行、273 个用例、5 套手工构造器）。

**已定的产品边界（2026-09-13 与产品负责人确认）**：语音双管线保留；Vision Guard/camera 全部保留；iOS 配对保留；WebUI 备份后删除；图谱退役（迁出新记忆底座需要的 `sensitivity.ts` 与可复用存储基础，同步改 03/06 spec）；Windows 原生防护层简化为 OS 原语；service.ts 必须拆；**多项目共享用户的 Codex HOME**；**runtime/src 根层 85 个平铺文件按职责归组**。

**诚实的算术**：在上述约束下，可删的生产代码约 **29k 行（≈25%）**，加上把评测脚手架搬出 src 约 2k（≈2%），JSON 账本 5.8k 不在分母内。**达不到 40%**。剩余 13% 只能来自语音管线合并（已排除）或 Orb/设置 UI 简化（约 2%，视觉会变）。约 29k 是待验证的净减预算，不是已证明的交付量；搬迁与目录重组只算组织改善，不计净删。批 7、8 的新增候选不叠加到原预算。

## 批 7：共享 Codex HOME 与凭据生命周期

### 7.1 目标与参考

参考仓库 `/Users/fishwowater/sqxh/nova-brain/thirdparty/qwen-audio-agent`：其 `server/src/agent/backends/codex.mjs` 将项目目录设为 cwd，继承环境，不为每项目创建独立 CODEX_HOME；模型配置经 ACP 适配器传递。职责划分可借鉴，ACP 专用环境协议不能直接视为 Nova app-server 的协议。

Nova 现状：`ProjectStore.createManaged` 创建工作目录，`persistentHome` 另行管理项目专属 Codex 状态目录。两者可解耦。

目标：多个项目共享用户选定的 Codex HOME，独立保留 cwd、thread、Nova workspace/session 绑定。Nova 继续新建目录、创建任务和生成标题；Codex 管理共享 HOME 中的认证与会话文件；Nova 所需执行配置通过经过验证的进程或请求级覆盖传递。

### 7.2 必须先处理的耦合

- `credential-snapshot.ts` 的非 preserveHome 路径会同步登录文件、写 config.toml，不能直接把路径改为用户 HOME。

- `factory.ts:104`：`generateTitles: project && !binding.preserveHome`；应按新建/续接和是否已有名称决定标题行为，不能因为共享 HOME 关闭标题。
- 新建与导入会话统一明确 HOME 绑定，保持同一 thread 的执行所有权，核查与外部 Codex 同时操作时的行为。
- 保留 shared-home 配置覆盖与实际 config/read 检查（`app-server-schema.ts:710–777` 的 `sharedHome` 分支），避免继承不符合 Nova 策略的扩展、MCP、环境和审批设置。
