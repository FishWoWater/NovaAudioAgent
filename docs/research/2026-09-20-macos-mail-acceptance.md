# Apple Mail connector — implementation and acceptance

Scope approved in conversation: readonly Apple Mail accounts/mailboxes, no API key, separate model-processing consent default off, and packaged-client live validation. The user then set a hard limit of the past 180 days and at most 500 message candidates per complete scan.

Implemented:
- Fixed Swift/ScriptingBridge helper uses Mail's installed scripting dictionary. Only status, request_access, list_mailboxes and snapshot are exposed; no send, save, mark-read, delete, attachment or arbitrary-script operation.
- Mail automation permission is separate from Calendar access. App usage text and a dedicated native-helper signing entitlement are included; helper launch reuses manifest verification and bounded subprocess I/O.
- Select existing mailbox folders and a 1–180-day window. Scan at most 500 candidates across selected folders in Mail's enumeration order, at most 20 date checks and eight message bodies per round. This is not a globally date-sorted newest-500 query. A page stops starting further messages after eight seconds of scan work, yielding its cursor early when Mail is slow. Each round has a 30-second host deadline and 2 MiB output ceiling; excessive bodies fail without checkpoint advancement.
- Durable source continuation/checkpoints, pause/resume/disconnect, generation-aware local delete, connection and object processing grants reuse existing source storage. Content retention is receipt +180 days. Read/flag metadata does not supersede content; identities separate accounts and mailboxes.
- Count/boundary changes restart a scan. Mail offset enumeration is not transactional, so missing messages never trigger inferred remote deletion, even below the cap; existing evidence expires under retention or explicit local deletion. A stable complete ID inventory is required before remote-deletion inference can be enabled. Reaching the 500-candidate cap is visible in the UI.

Verification so far:
- Native helper compiles and rejects `send` as unsupported; host rejects unlisted commands and out-of-range scopes.
- New behavior tests cover account isolation, read-state invariance, 180-day retention, scope mismatch, continuation, preserving evidence after incomplete/capped scans, pause and disconnect. Related native/calendar/sync tests passed. A native executable check covers Apple-event timeout/permission error propagation; a concurrent refresh regression first reproduced duplicate connection rows and now passes with atomic row replacement. The final targeted run passed all seven tests.
- Desktop build and local package generation passed; ad-hoc development signing plus final native resource manifest verification passed. Changed TypeScript lint and whitespace checks passed.
- Final desktop full suite: 936 tests, 933 passed, 3 skipped, zero failures. Source startup smoke reported skipped, not passed.
- First runtime full suite: 2579 tests, 2567 passed, 8 skipped, four failures. Three were realtime-assembly startup deadline tests (cumulative progress, initial Header delivery, concurrent starts); one was remote-personal-memory unavailability. Both files rerun independently: 82 passed. Full rerun at concurrency 4: 2569 passed, 8 skipped, two realtime-assembly startup deadline failures (ordered object graph and Qwen controller-bearing approval). This suite is not green; isolated success does not prove default parallel stability.

Live status: the user granted Nova permission to control Mail. The original packaged Nova UI enumerated 17 mailbox folders; only the approved Google account's existing INBOX was selected, with 180 days and model processing off. Pause, disconnect-with-retention, resume, and persistence of the paused state across restart were exercised in Nova. Native Calendar pause/disconnect/resume also passed; its 15 objects remain present.

Live validation found and fixed three defects: Apple-event timeout units are ticks (60/second), and failed counts had incorrectly looked like empty successful snapshots; the native delegate now fails closed. Concurrent source refreshes could duplicate displayed connections; rows are now replaced atomically. Named mailbox references and bounded ID queries avoid repeated indexed lookup. A later eight-message page repeatedly exhausted its deadline; elapsed-time yielding advanced that same saved position from 66 to 69 without increasing the deadline. The first failed/empty scan is not counted as acceptance evidence. A second static review of these fixes found no confirmed P1/P2 issue.

The current clean local package opens its window and starts its runtime. Temporary startup diagnostics were removed by rebuilding, and packaged runtime/main bytes plus the native helper hash were checked against the build. Earlier ad-hoc development-signed launches either had no window or failed backend assembly; that signing/startup difference remains unresolved and is not a release validation. Existing Google/native Calendar evidence remains in the earlier connector acceptance report. No real email or calendar event was created, modified or deleted.

An independent readonly helper probe resumed at candidate 498 of the real 5,031-message mailbox and returned complete=true, capped=true, cursor=null; those final candidates were outside the date window and returned zero bodies. This boundary probe did not change the product checkpoint or substitute for a full product scan. The complete product scan is blocked by intermittent Mail body timeouts; 85 real messages were durably imported before stopping for diagnosis. Final complete-batch acceptance is not claimed. All observed extraction counts remain zero.

Performance investigation requested by the user:
- Instrumented the actual getters without logging content. Ordinary fields took approximately 1–16 ms, while one full message.get() took 6.5 s, indexed IDs took 0.6–3.2 s, and repeated mailbox counting/boundary checks added seconds per page. These are individual observations, not controlled benchmark medians.
- Replaced full message.get() and per-message indexed ID reads with fixed, readonly Apple get-data range requests (at most eight IDs, every requested index in 1…500), followed by ID-addressed field reads. A real eight-ID request took 0.16 s; a separate first-eight probe took 0.88 s. Native range guards are tested; a second reviewer found no confirmed P1/P2 issue. Reference: [Apple range descriptors](https://developer.apple.com/documentation/coreservices/formrange).
- Body reads remain variable (one observed call was 7.18 s); an initial combined plain/rich-text probe timed out without isolating which getter failed. A later plain-only probe hit its ten-second deadline; a separate diagnostic with a twenty-second deadline returned in about four seconds. Product deadlines were not increased. Mail's own Connection Doctor reported Google IMAP and SMTP unavailable while another configured account connected successfully. Separate unauthenticated TLS probes to imap.gmail.com:993 and smtp.gmail.com:465 both failed with SSLEOFError before login. This confirmed a Google mail transport failure at that time; waiting for uncached bodies is a plausible remaining contributor, not a proven explanation for every slow call. No TLS or proxy setting was changed.
- The final batch implementation's candidate-498 boundary probe returned complete=true/capped=true with zero out-of-window bodies. It did not alter the product cursor. Product-wide 500-candidate completion remains unverified until the Mail connection works reliably.

Follow-up after excluding Google from native Mail:
- Google TLS probes and Mail Connection Doctor subsequently recovered, but body reads still timed out intermittently. Network recovery did not eliminate the native Mail bottleneck.
- A per-message Apple-event timeout now returns the already completed prefix with complete=false and the cursor before the failed message. This preserves good messages without skipping the failed item or claiming a complete scan. Batch-ID errors and the overall process deadline still fail the entire page. A native regression first failed without the callback, then passed; the five targeted Mail/connector tests, desktop rebuild and package generation passed. Static review found no confirmed P1/P2 issue.
- At the user's request, Nova's saved native Mail scope now selects only the non-Google account's existing INBOX, with 180 days and model processing off. Google folders are unchecked; the independent Composio Gmail connection is unchanged. No Mail account or transport settings were modified.
- After graceful shutdown, persisted scope revision 3 contained one selected folder. Nineteen messages from that selected account were stored, with continuation offset 19; that account also encountered a body-read timeout. There were 106 retained Mail objects in total, including earlier Google objects, and zero model extractions. Excluding Google alone does not resolve all Mail body latency. A complete 500-candidate product scan remains unverified.
