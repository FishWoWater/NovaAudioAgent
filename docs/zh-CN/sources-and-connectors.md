# 资料来源与连接器

小诺只读取你明确连接的资料——本地文件夹、邮件与日历，还有飞书会话——并且只有在你另外同意之后，才会把这些内容交给模型处理。

## 连接、同意处理、暂停、断开、删除

| 操作 | 作用 |
|---|---|
| 连接 | 授予访问权限：一个文件夹、一个账号，或者一批会话 |
| 同意处理 | 单独的开关，允许配置好的模型服务读取内容；连接了资料不代表已经同意 |
| 暂停 | 保留连接和已经收集的内容，只是不再读取新的 |
| 断开 | 停止在本机收集，但保留已收集的数据（飞书还会保留应用配置）。对通过 Composio 连接的服务，这不会撤销你给出的 OAuth 授权，需要的话请到 Composio 或对应服务里单独撤销 |
| 删除历史 / 本地数据 | 清除已收集的内容，这是独立于断开连接的另一步操作 |

## 本机文件

在设置的「本机资料」标签页里，必须先勾选同意，才能使用「选择文件夹」或「授权所有可访问的本机文件」。每个来源每轮同步最多读取 1 到 200 个文件、合计不超过 20 MB；超出的部分会顺延到之后的同步里，并不是累计上限。支持的类型包括纯文本、Markdown、JSON、YAML、CSV、常见源代码后缀、PDF 以及 Word（`.docx`）。

版本控制、构建产物、依赖和缓存目录，以及浏览器的配置目录，会被自动排除。隐藏文件和隐藏目录默认跳过，除非你按名字单独选中；项目本身在 Git 里忽略的内容同样会跳过。全盘授权模式还会排除系统和应用程序目录，依然遵守操作系统的文件权限，分批处理，暂停后立刻停止读取。

## 邮件与日历

| 来源 | 扫描范围 | 每轮检查量 | 保留时长 |
|---|---|---|---|
| macOS 邮件 | 最近最多 180 天 | 最多 500 封 | 收到后保留 180 天 |
| macOS 日历 | — | 每页最多 200 个事件 | 事件结束后保留 30 天 |
| Composio Gmail | 自上次同步起，首次为快照 | 每页最多 200 条待处理变更、8 封正文 | 邮件时间起保留 30 天 |
| Composio 日历 | 一段可配置的前后天数窗口 | — | 事件结束后保留 30 天 |

macOS 邮件与日历直接使用你 Mac 上已有的系统应用。Composio 通过自己的 OAuth 流程在任意平台上连接 Google 邮件和日历，并限制单台主机最多同时保留 20 个来源连接。较长的正文会被截断（约 99000 字符），并附一句提示告诉你去哪里看完整内容。

## 飞书

飞书接入用的是你自己的飞书应用，通过 `lark-cli` 完成——没有内置应用，也不共享任何凭证。连接器要求 `lark-cli` 版本不低于 1.0.69，版本过旧会直接拒绝。

1. **连接应用**——在飞书官方开发者页面新建一个，或者绑定已有的应用，填入 App ID 和 Secret。Secret 只通过标准输入传递，绝不会作为命令行参数出现；已经绑定过的应用不会被静默替换。
2. **登录账号**，走一遍 OAuth 的设备码授权流程。
3. **选择会话**——按真实名称挑选要同步的会话，没有预设分类。

需要的权限包括读取会话列表、读取消息、读取消息表情回应，以及 OAuth 的离线访问权限。首次同步覆盖最近 7 天，之后从上次的位置继续。文本和富文本消息会被保存；不下载附件，只会显示一条提示。只记录真人发的消息，机器人自己发的消息不会被重复收录。消息内容保留 30 天。

两项同意是分开的。选择会话时，你允许小诺读取这些会话并把消息保存在本机；另一个开关用于允许设置中的模型服务处理飞书内容，决定这些消息能否交给你配置的模型来整理成记忆。它默认关闭，只属于当前登录的账号，换账号、登录过期或模型服务变更时会被清除。没有开启时，小诺不会把这些消息用于记忆。

两项都开启后，你所选会话里直接 @ 你的消息会被记为待办，并标明来源。只收录从「选择该会话」与「同意处理」两个时刻中较晚的一个起的 @ 提及，更早的历史不会变成待办。待办在未被修改前可以撤销。

飞书登录过期后，小诺会暂停同步和机器人提醒，并在飞书卡片上提供重新授权按钮。应用绑定、已选会话和本地历史都会保留，无需重新绑定应用。

机器人提醒是可选开启的功能，只会发到你和机器人的私聊，不会发到群里。提醒卡片可以打开、稍后提醒或忽略；打开卡片只是跳转到小诺，不代表授权它执行任何操作。凭证保存在独立目录里，和其他应用的登录信息互不共享。

断开连接会清除登录状态，但保留应用配置和历史记录；删除历史会清除已收集的消息以及由它们生成的记忆，这是独立于断开连接的另一步；之后重新连接会从头开始新一轮收集。

## 扫描与画像更新

飞书会话最多同时扫描四个，一页文字消息用一个 ledger 事务入库，仅在资料或处理授权变化时刷新来源上下文。缺少结构化 @ 信息时，补查原消息共用最多四个请求位；本人消息不需补查。新扫描窗口按时间倒序；历史补扫保留自己的分页位置，与后续新消息窗口分别推进，每轮最多读取 20 页历史和 2 页新消息。旧版未完成的分页继续使用原顺序，避免换序后跳过消息。单个会话失败不会阻塞其它已选会话。

Composio 来源最多同时同步四个；Gmail 正文每批最多并发读取四封，每轮仍最多八封，并保留原有请求预算。失败的批次保留待处理位置，下一轮可以重试。邮件历史变更按服务端游标推进，不能套用飞书消息的倒序分页。本机最多同时扫描四个文件夹来源，各自保存恢复断点，仍遵守文件与字节预算；同一来源内的文件提交保持顺序。文件索引按路径查询，避免逐文件返回整个索引。本机邮件和日历保持各自的原生分页。共享记忆提取最多同时处理四条资料，优先处理直接 @ 的消息，再按资料时间从新到旧处理。并发结果仍检查授权和记忆版本；冲突项保留待处理记录，之后重试。

Profile 从第一批可用资料开始计时，在累计 5 分钟、30 分钟、4 小时各生成一次，不等待所有渠道扫描结束。之后有新资料时，每隔至少 4 小时再更新；计时与阶段会保存，重启后继续。手动刷新可以提前生成。每次更新结合现有画像与当前资料，保留仍有有效依据的工作和兴趣；失效或撤回授权的依据会被移除。

除了项目文件，Profile 可以使用已同意模型处理的本人飞书消息、直接 @ 本人的消息和本人发出的 Gmail 邮件。Gmail 必须同时具有已发送标签和与连接账号一致的发件地址；收件正文和未直接 @ 本人的消息不加入这条输入路径。直接 @ 内容标为外部请求，不当作本人确认或完成。原生邮件和日历没有相同的本人身份校验，不直接加入这条画像输入路径。内容以有限样本提交，画像不保证覆盖所有历史。

消息画像保留原始时间、稳定的发送者编号、可用显示名、会话和 @ 对象；本人发出的邮件也保留邮件会话与收件对象。先过滤凭据，再按批次最多四路整理，未变化的批次摘要可在当前运行中复用。最终画像另做一次证据核查，区分发言者、请求对象和实际执行者，以及计划、完成、取消和回退。受样本与模型判断影响，结果仍是可编辑的建议。已完成会话的未变化扫描窗口不重复读取，新消息和未完成分页照常继续。

可用的回复和转发关联 ID 会随证据保留，CLI 的 `reply_to` 归一为 `parent_id`。关联只说明消息上下文，不代表引用正文的作者；授权画像样本外的关联目标明确标记为不可用。结构化核验保留原消息的来源 ID，后续草稿不会自动复活已省略的消息推断。

画像先用批次索引选择关键原消息；索引只用于选材，不作为事实。较大输入再选择最多40条代表性原文，并把模型引用重新编号为连续短 ID，返回时恢复原来源 ID 和版本。之后一次自然成文、一次整份原证据审查，再把审查反馈交给一次整份编辑，统一摘要、工作和兴趣里的归属与计划状态；编辑说明独立保存，不混进正文。允许有依据的主题归纳和适度发挥，正文围绕工作主线、关注点与协作关系写自然段，不自动插入日期或列阶段履历。本地只检查结构、来源、授权和显式凭据，不根据关键词猜语义。发送者和正文作者分开：消息带平台发送者、显示名及正文作者未验证的标记，本人发送不等于本人写了全部正文或执行了其中成果。引用与助手回报可帮助理解推进方向，不能直接记成本人的完成成果。配置的 Qwen3 VL Plus/Flash 使用有限思考预算；其思考请求不混用不保证结构的 JSON 模式，输出仍做本地结构校验与一次格式重试。结果受选材和模型判断限制，仍是可编辑建议。

产品默认保留正常上下文，包括姓名、邮箱、网址、机器地址及普通代码串，不以字段或字符串外观猜测敏感内容。只处理明确标注或直接可识别的密码、API key、token、私钥及携带凭据的链接；多行凭据保留同条消息中的其它内容。未标注的秘密不会靠外观猜测识别。

画像生成器可注入独立的模型接口做整份编辑复核；未指定时仍使用当前生成模型。这是通用接口选项，不内置 CLI 依赖，也不自动切换到第二家模型服务。持久化的画像输入指纹包含生成规则版本，规则更新后，即使来源没变，也可以重新生成。
