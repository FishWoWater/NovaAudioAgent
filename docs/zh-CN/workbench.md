# Workbench

Workbench 是小诺的主窗口，默认打开宽主对话 Nova，位于左侧；右侧是工作区，顶部页签依次是 Timeline、想法、目标、资讯、任务和「个人资料」。

## 布局

[![Nova 工作台与下一步建议](../../assets/features/workbench-original.png)](../../assets/features/workbench-original.png)

| 工作区页签 | 内容 |
|---|---|
| Nova | 持续保留的主对话，承接主动提醒与任务回执 |
| Timeline | 简报卡片，下方是「我的待办」：已有的待办条目按截止日期分组，可标记完成、改状态和截止日期，也可从卡片发起讨论 |
| 想法 | 还没定下来的念头，之后可以转成待办或目标 |
| 目标 | 你在追踪的结果，带成功标准，进度来自关联的待办 |
| 资讯 | 按兴趣排序的阅读列表 |
| 任务 | 交给 executor 执行的工作，详见[任务](tasks.md) |
| 个人资料 | 小诺了解你的一小段自我介绍 |

切换页签时，Nova 对话始终留在左侧；「收起」按钮会把窗口缩成悬浮球。状态栏会显示小诺是否已连接、有多少后台任务在跑；断线期间正在写的内容不会丢，等重新连上还在。

## 切换小诺的呈现方式

小诺有三种呈现方式：Workbench（这个主窗口）、悬浮球（一个小的浮动对话入口），或者隐藏。可以在托盘菜单里切换（对应「工作台」「悬浮球」「隐藏」），也可以在 Workbench 任意页面顶部的模式选择器里切换。另有一项独立的设置决定启动时默认打开哪一种——悬浮球、Workbench，还是沿用上次的选择——只在下次启动时生效；从源码运行时执行 `npm run start:workbench` 会为这一次启动强制打开 Workbench，不理会已保存的偏好。

## Chat、Plan 与 Build

工作台对话有 Chat、Plan 和 Build 三种模式。新普通会话从 Chat 开始；切换这些模式不会改变工作台和悬浮球原有的权限边界。

- **Chat** 保持现有对话能力，可回答问题，也可按用户要求把工作交给执行器，并跟踪现有任务进展。你也可以直接要求 Nova 进入 Plan。它和悬浮球一样，不能直接读取或修改本机文件，也不能运行 shell 命令。
- **Plan** 用文字澄清目标、范围、约束和验收标准，必要时会追问模糊点。它没有本机文件或 shell 工具，也不会在用户选择前创建或派发任务。计划发布后可以修改，再选择在当前项目 Build，或交给执行器 Build。
- **Build** 只支持文字，执行用户确认的计划。macOS 和 Windows 上可以使用本机文件读取、写入、精确编辑及 shell 工具；Linux 和其他不支持的平台不会显示本地 Build 入口。所选项目目录是默认工作目录，工具按当前系统用户权限访问本机资源。

本地 shell 只继承必要的系统变量和开发环境变量（例如 PATH、临时目录、语言设置、DEVELOPER_DIR、SDKROOT、VIRTUAL_ENV），不会自动继承宿主的第三方 API 密钥、代理配置或脚本注入变量。Windows PowerShell 使用系统内置模块目录，不继承外部模块搜索路径。依赖这些环境变量的命令需要在项目中另行配置；这不限制命令按当前用户权限读取文件。文件分页在行中截断时使用返回的字节游标续读，避免漏读；写入悬空符号链接会明确失败并保留链接。

本地 Build 不创建任务或待办，也不会在后台自动续跑。文件读取最多返回 2000 行或 64 KiB，文本写入和精确编辑最多处理 1 MiB；shell 默认 60 秒超时（可设为 1–3600 秒），标准输出和错误输出合计最多保留 64 KiB。命令主进程退出后，宿主清理遗留子进程并保留真实退出码。Build 可在运行期间接收后续消息，并按顺序处理；每次启动或 Resume 最多执行 128 次工具调用，单次模型回复最多接受 64 次调用。达到轮次上限后会暂停，用户可点击 Resume 继续。较长回复可展开加载完整内容。Build 默认可继续交互；仅当 Nova 调用 `finish_build` 后会永久锁定该会话。运行中切换悬浮球、隐藏显示或离开 Build 会话时，工作台会先询问是否停止；停止后需要用户明确 Resume 才会继续。应用重启后也不会自动恢复工具执行授权。

本地文件读取直接执行；文件写入、编辑和 shell 命令默认逐次向用户确认。可在「设置 → 编程 → 本地 Build 工具」改为无需确认；这项设置只影响工作台本地 Build，与执行器审批分开。持续语音仍使用 Chat；从 Plan 或 Build 启动语音会先切回 Chat。

Plan 和 Build 支持模型在同一轮返回多个工具调用，两种模型协议（Chat Completions / Responses）均会为每次调用保留独立结果。连续的独立只读查询最多同时执行 4 个；写入、编辑、shell、计划发布和其他操作按顺序执行，并等待此前查询结束。Plan 每次交互最多 24 次调用；Build 单次模型回复最多 64 次调用，每次启动或 Resume 最多 128 次。停止、审批和恢复也分别保留各项调用状态。一次 Build 交互中的工具调用会合并为可折叠记录，每个工具条目可单独展开。

Build 对话会实时显示每次工具调用，包括读取、写入、精确编辑和 shell 命令。每行显示路径或命令、执行状态、耗时及退出码；展开可看精简的输入输出。输出在工具返回后更新，完整记录可通过「执行记录」查看。展开状态会随运行保留，重新打开会话或刷新界面也会恢复操作记录。

Build 没有整轮 120 秒的总期限；模型连接连续 10 分钟未返回数据时才按空闲超时暂停。长回复与代码生成使用更大的流容量；模型超时、连接中断或回复超出容量时，会说明原因并提供 Resume，已完成的工具不会重放。每条 shell 命令仍遵守自己的超时。

## 想法与目标

这些内容你可以直接编辑，小诺也会主动提建议。当你说的话像一条想法、目标或「个人资料」的补充时，小诺会把它作为候选展示出来，并附上依据的原话；确认前可以先改好措辞，也可以直接略过。「个人资料」的建议是追加到已有内容后面，不会替换掉原有的介绍。小诺不会自动生成待办：没有待办页签，也不会有待办被自己记下来。

来自你已连接资料的建议卡片，会提示把某件事记成想法或设为目标、接着聊，或者直接隐藏。

目标的待办进度只统计关联的待办，且不计入已取消的部分；目标是否真正达成，永远由你确认，不会被自动判定完成。

Nova 可以根据最近的对话提议长期目标，只有点击「设为目标」后才会创建。目标可选择每日问候、按进展跟进或不主动提醒。点击 check-in 的「回复进展」再回复，目标卡会更新派生的进展摘要；暂停目标会停止问候。主动消息默认每天最多 5 条，可在「设置 → 通用 → 主动性」调整。

在你给出两项飞书同意之后，所选飞书会话里直接 @ 你的消息会进入 Timeline 简报，不会被记为待办；详见[信息来源与连接器](sources-and-connectors.md#飞书)。

## 每日简报

可选的早间和晚间简报，会把你的待办、日历事件和飞书中直接 @ 你的消息整理成主动提醒。两者默认都关闭。在「设置 → 通用 → 主动性 → 每日简报」中开启，也可以在这里设置时间（默认 08:30 和 18:30）、重复日期（默认工作日）、时区和免打扰时段（默认 22:00 至 08:00）；免打扰期间不发送提醒。

## 每日日记

「个人资料」里的每日日记根据昨天改动过、允许模型处理的记忆整理，默认开启，可在主动性设置中独立关闭。没有符合条件的记忆就不生成，也不会补写更早的日期。日记保留原始记忆引用，只供展开阅读和删除，不进入检索或后续模型上下文；删除日记不会删除原始记忆，也不会重新生成当天日记。

从卡片新开对话时，引用内容在普通聊天中传入。带引用的对话不会自动切到 Plan；Build 仍需计划和独立授权。

## 资讯

按你的兴趣排序的文章，分「为你推荐」和「收藏」两个标签。小诺还没摸清你的口味之前，会先按时间顺序展示，并在准备切到兴趣排序前先跟你确认一下。每篇文章都会说明推荐的理由。你可以打开原文、收藏，或者把它转成一条 Todo、想法或目标——这些动作都只是记录下来，不会让小诺去执行任何操作。也可以告诉小诺哪类兴趣想多看、哪类想少看。

## Nova 主对话与 Timeline

Workbench 默认打开 Nova。主对话持续保留，主动提醒和任务回执在主线中展示；任务详情、专用对话与语音归属仍各自独立。完整时间线从第一个页签打开。

简报卡片下方的「我的待办」使用已有待办条目的真实截止日期分组，未设期限的等待事项单独展示；每条待办可标记完成、改状态或设置截止日期。蓝色标签表示时间，玫瑰色表示用户标记的重要性，紫色表示等待，绿色表示进展，琥珀色表示已过截止等需要留意的条件；颜色同时配有文字。重要性可用时间线卡片上的星标设置，会写回原事项。日历完整性暂未确认，时间线不代表完整日程。

待办的 `due` 是可为空的日期（`YYYY-MM-DD`），创建和更新时间不会被当作期限。飞书 @ 提及是简报的输入，不是待办。这版展示日期安排，尚不计算小时级冲突。

点击事项标题可在 Nova 中引用讨论，所有卡片共用同一个讨论动作；“排一版方案”和“起草跟进”会带该事项请求产物。引用可移除，发送时重新校验版本，消息草稿与执行审批继续保留。资讯可只讨论文章，也可由你选择待办或目标后整理应用思路；兴趣匹配不会自动变成个人事项关联。
